# Frontend Design Guidance Summary

This resource provides design leadership for creating distinctive, non-templated web interfaces. The core philosophy centers on grounding design choices in the subject matter rather than defaulting to common patterns.

## Key Principles

**Subject-First Approach**: "name one concrete subject, its audience, and the page's single job" before designing. The subject's own world should inform palette, typography, and layout decisions.

**Typography as Personality**: Rather than neutral delivery, typeface pairing should be deliberate and specific to each project, establishing a memorable type system with intentional scale and weight.

**Structural Integrity**: Design elements like numbering or dividers should encode genuine information about content, not merely decorate it. For instance, numbered sequences only make sense when order actually matters.

**Avoiding Default Patterns**: The guide identifies three common AI-generated aesthetics to consciously avoid—cream backgrounds with serif/terracotta, dark backgrounds with acid-green accents, and broadsheet-style layouts—unless the brief specifically calls for them.

## Process Framework

The recommended workflow involves two passes: first, develop a compact token system addressing color, typography, layout, and signature elements; second, critique against the brief to ensure choices feel specific rather than generic before building.

**Motion and Restraint**: Animation should serve the subject deliberately, and boldness should concentrate in one memorable signature element while surrounding design remains disciplined.

**Writing as Design**: Copy exists to aid understanding and navigation, written in active voice with specific, plain language that maintains consistency throughout the user experience.
